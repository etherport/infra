# cue-db — PostgreSQL for the Cue app

A dedicated single-instance [CloudNativePG](https://cloudnative-pg.io) cluster for
the **Cue** app's database. Cue owns its schema (Drizzle migrations run by the
app), so this only provides the database, role, and extension — no tables.

| | |
|---|---|
| Namespace | `cue` |
| CNPG Cluster | `cue-db` (1 instance) |
| Image | `ghcr.io/cloudnative-pg/postgresql:16.4` (PG 16.4) |
| Database | `cue` (UTF8) |
| Role | `cue` — login, non-superuser, **owner** of `cue` (full DDL/DML) |
| Credentials Secret | `cue-db-app` (auto-generated by CNPG; strong random password — never in git) |
| Services | `cue-db-rw` (read-write, use this), `cue-db-ro`, `cue-db-r` — all `:5432` |
| Storage | `ceph-rbd` 5Gi (online-expandable) |
| Extensions | `vector` (pgvector 0.8.0) **pre-enabled**; `gen_random_uuid()` is core |

## Why `vector` is pre-enabled
pgvector ships in the image but is **not a "trusted" extension**, so the
non-superuser `cue` role can't `CREATE EXTENSION vector` itself. It's enabled
once at bootstrap (`postInitApplicationSQL`, as superuser). The app's
`CREATE EXTENSION IF NOT EXISTS vector` migration is then a harmless no-op — if a
migration uses bare `CREATE EXTENSION vector` it will error (already exists), so
keep the `IF NOT EXISTS`.

## Connecting

**In-cluster (app Deployment, later):**
```
postgres://cue:<password>@cue-db-rw.cue.svc.cluster.local:5432/cue?sslmode=require
```
The app should read these from the `cue-db-app` Secret (keys: `username`,
`password`, `uri`, `host`, `port`, `dbname`) rather than hardcoding. CNPG also
publishes a ready `uri` key.

**Tailnet (devs, preferred):** the primary is exposed tailnet-only via the
Tailscale operator (`02-tailscale-svc.yaml`, `loadBalancerClass: tailscale`) at
**`cue-db.tail48f596.ts.net:5432`** — no public IP. Access is governed by the
tailnet ACL (`infra/tailscale/policy.hujson`, currently allow-all). From any
tailnet device:
```
PW=$(kubectl get secret cue-db-app -n cue -o jsonpath='{.data.password}' | base64 -d)
export DATABASE_URL="postgres://cue:${PW}@cue-db.tail48f596.ts.net:5432/cue?sslmode=require"
pnpm db:migrate   # / db:studio / run the app
```

**Local dev (alternative, no tailnet):** port-forward:
```
kubectl port-forward -n cue svc/cue-db-rw 5432:5432
# in another shell — fetch the password into DATABASE_URL:
PW=$(kubectl get secret cue-db-app -n cue -o jsonpath='{.data.password}' | base64 -d)
export DATABASE_URL="postgres://cue:${PW}@localhost:5432/cue"
pnpm db:migrate   # / db:studio / run the app
```
TLS: not required (CNPG accepts non-TLS; the port-forward is already tunnelled
through the API server). Add `?sslmode=require` to encrypt to the pod, but **not**
`verify-full` over port-forward (the server cert CN is the cluster name, not
`localhost`).

## Ops
- **Scale to HA**: bump `spec.instances` to 3 (operator handles failover; storage
  class supports it). Currently 1 (single-user dogfood).
- **Backups**: none configured yet (the shared `postgres-cluster` uses Barman→S3).
  Nice-to-have follow-up: a daily `pg_dump` CronJob or wire Barman with its own
  S3 prefix. Data is currently regenerable (app owns the schema in git).
- **Superuser** access is disabled (CNPG default). Re-enable via
  `spec.enableSuperuserAccess: true` only if you need it.

## Future: hosting the Cue app here
When Cue is containerised, add an app `Deployment` + `Service` in this `cue`
namespace that mounts the `cue-db-app` Secret as env (e.g. project `password`/
`uri` into `DATABASE_URL`). A Helm chart / Dockerfile comes with containerisation.
